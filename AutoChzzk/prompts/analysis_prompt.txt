# AutoChzzk Broadcast Analysis Prompt

## 1. 분석 목적

제공된 방송 자막과 채팅 통계를 분석하여
방송 전체를 빠짐없이 시간 순서대로 구간별로 요약하고,
각 구간의 재미(fun_score)와 시청자 반응(reaction_score)을 점수로 평가한다.

이 분석의 목적은 하이라이트를 골라내는 것이 아니다.
방송의 모든 시간대가 어떤 내용이었는지 기록하는 것이다.
클립 후보 선별은 이 결과의 점수를 이용해 이후 단계에서 따로 수행한다.

따라서 재미가 없거나 의미 없는 구간도 생략하지 않고 반드시 포함한다.


## 2. 작업 순서

반드시 아래 순서로 진행한다.

1단계: 대단위 요약 (outline)
- 방송 전체를 처음부터 끝까지 큰 흐름 단위로 나눈다.
- 주제, 활동, 게임 회차(매치)가 바뀌는 지점에서 구분한다.
- 여러 판의 게임이 있는 방송은 판이 바뀌는 지점을 반드시 대단위 경계로 삼는다.
- 이 단계에서 방송 전체 시간이 빈틈없이 덮여야 한다.

2단계: 세부 구간 분할 (events)
- 1단계의 각 대단위 안을 실제 장면 단위의 세부 구간으로 나눈다.
- 각 세부 구간의 summary를 먼저 작성한 뒤, 점수를 평가한다.

점수는 구간을 나누고 요약한 이후에 평가한다.
"점수가 높아서 구간으로 선택한다"가 아니라
"이미 나눈 구간의 특성을 점수로 평가한다"는 원칙을 따른다.


## 3. 구간 분할 규칙 (가장 중요)

- 첫 구간의 start는 자막의 첫 시작 시간과 같아야 한다.
- 마지막 구간의 end는 자막의 마지막 시간(또는 방송 길이)과 같아야 한다.
- 구간은 시간 순서대로 이어지며, 이전 구간의 end와 다음 구간의 start는 같아야 한다.
- 빈 시간(gap)도, 겹치는 시간(overlap)도 없어야 한다.
- 자막이 없는 구간(침묵, 대기, 화면만 진행되는 구간 등)도 생략하지 않고
  하나의 구간으로 만들어 그 사실을 summary에 기록한다.
- 음악이 재생 중인 구간은 곡 정보를 추측하지 말고
  summary에 "음악 재생 중"이라고만 기록한다.
  음악 중에 말이 섞여 있으면 말의 내용을 요약하고 "음악 재생 중"을 덧붙인다.
- 구간은 시간이 아니라 주제나 장면이 바뀌는 지점을 기준으로 나눈다.
  서로 독립적인 장면이 하나의 구간에 섞이지 않게 한다.
- 한 구간은 가능하면 {max_event_interval_sec}초를 넘지 않게 한다.
  단, 하나의 장면이 자연스럽게 더 길다면 억지로 자르지 않는다.
- 길이를 맞추기 위해 장면을 억지로 자르거나 합치지 않는다.
- 잡담, 일상 대화, 의미 없는 구간도 짧게 요약해서 반드시 포함한다.
- 점수가 낮다는 이유로 구간을 생략하거나 다른 구간에 합치지 않는다.


## 4. 점수

두 점수는 서로 다른 데이터를 근거로 평가하며, 서로 독립적이다.
한 점수를 정한 뒤 그에 맞춰 다른 점수를 정하지 않는다.
각 점수는 0~10의 정수이다.

### fun_score: 자막 내용만 보고 평가

- 자막에 나타난 말의 내용만 근거로 평가한다.
- 채팅 데이터는 fun_score에 절대 반영하지 않는다.
  채팅이 많든 적든 fun_score는 달라지지 않는다.
- 자막에 없는 상황(표정, 화면, 목소리 톤 등)을 추측해서 평가하지 않는다.
- 다음과 같은 요소를 중점으로 본다.
  드립, 말장난, 티키타카, 황당하거나 뜻밖의 상황, 찬반 토론이나 갈등,
  놀림, 캐릭터성이 드러나는 발언, 자막만 봐도 이해되는 웃긴 상황
- 기준:
  - 0~2: 잡담, 진행 멘트, 대기, 무음, 음악, 단순 정보 전달
  - 3~4: 약간 흥미로운 대화, 소소한 웃음 포인트
  - 5~6: 재미있는 대화가 이어지는 구간
  - 7~8: 독립 클립으로 쓸 만한 웃긴 장면
  - 9~10: 자막만 봐도 확실히 터지는 장면
- 재미없는 구간에 점수를 후하게 주지 않는다.
  낮은 점수(0~2)를 주저하지 않고 부여한다.

### reaction_score: 채팅 수의 평균 대비 배율로 평가

- 해당 구간의 채팅 수를 방송 전체 평균 채팅 수와 비교한 배율만 근거로 평가한다.
- 자막 내용이 재미있어 보인다는 이유로 reaction_score를 올리지 않는다.
- 채팅이 적다는 이유로 내용이 재미없다고 판단하지 않는다.
- 구간이 여러 채팅 집계 단위에 걸쳐 있으면
  해당 구간의 평균 배율과 최대 배율을 함께 고려한다.
- 기준:
  - 0~1: 평균의 0.5배 미만
  - 2~3: 평균의 0.5배 이상 1배 미만
  - 4~5: 평균 수준 이상 1.5배 미만
  - 6~7: 평균의 1.5배 이상 {chat_spike_threshold}배 미만
  - 8~10: 평균의 {chat_spike_threshold}배 이상 (급증 구간)
- 채팅 데이터가 없거나 해당 구간의 채팅을 확인할 수 없으면
  reaction_score는 0이 아니라 null로 기록한다.

### 두 점수의 조합 예시

- fun 낮음 + reaction 높음: 일상 대화인데 채팅이 크게 늘어난 구간
- fun 높음 + reaction 낮음: 재미있는 대화인데 채팅은 조용한 구간
- 둘 다 높거나 둘 다 낮은 경우도 정상이다.


## 5. 채팅 데이터

채팅 수가 평균의 {chat_spike_threshold}배 이상 증가한 구간은
다른 구간에 묻히지 않도록 별도의 구간으로 분리한다.

일상적인 이야기에서 채팅이 급증했더라도 구간으로 남긴다.
이 경우 fun_score는 낮고 reaction_score는 높게 기록될 수 있다.

채팅 데이터는 reaction_score와 구간 분리 판단에만 사용한다.


## 6. 제목과 요약

title은 해당 구간의 핵심 화제를 짧고 자연스럽게 표현한다.
딱딱한 문어체나 보고서 말투는 피한다.

summary는 해당 구간에서 실제로 일어난 일을 1~2문장으로 요약한다.
자막에 화자 구분(화자 A, B, C 등)이 있으면
누가 무엇을 했는지 구분해서 적는다.

제목과 요약에는 자막과 채팅 데이터에서 확인할 수 있는 내용만 사용한다.
입력에 없는 사실이나 상황을 추측해서 추가하지 않는다.


## 7. 출력 전 자체 검증

출력하기 전에 다음을 확인하고, 어긋나면 수정한 뒤 출력한다.

- 첫 구간 start와 마지막 구간 end가 전체 범위를 덮는가
- 모든 구간에서 이전 end와 다음 start가 일치하는가
- 채팅 급증 구간이 별도 구간으로 분리되어 있는가
- 점수가 낮은 구간이 생략되지 않고 포함되어 있는가
- fun_score가 채팅이 아니라 자막 내용으로만 평가되었는가
- reaction_score가 자막 내용이 아니라 채팅 배율로만 평가되었는가
- outline의 각 대단위가 events의 시간 범위와 일치하는가


## 8. 출력 형식

반드시 아래 JSON 객체만 출력한다.
추가 설명이나 Markdown 코드블록은 출력하지 않는다.

{
  "outline": [
    {
      "start": 0,
      "end": 600,
      "title": "대단위 주제",
      "summary": "이 큰 구간의 흐름 요약"
    }
  ],
  "events": [
    {
      "start": 0,
      "end": 95,
      "title": "구간 제목",
      "summary": "이 구간에서 일어난 일 요약",
      "fun_score": 2,
      "reaction_score": 1
    }
  ]
}

각 필드의 의미:

- start: 시작 시간(초)
- end: 종료 시간(초)
- title: 제목
- summary: 구간 내용 요약
- fun_score: 자막 기반 재미 점수 0~10
- reaction_score: 채팅 배율 기반 반응 점수 0~10, 채팅 데이터가 없으면 null
