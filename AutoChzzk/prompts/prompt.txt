# AutoChzzk Highlight Analysis Prompt

## 1. 분석 목적

제공된 방송 자막과 채팅 통계를 분석하여
키리누키/클립으로 사용할 가치가 있는 장면을 찾아낸다.

단순히 방송 내용을 요약하는 것이 목적이 아니다.

하나의 큰 주제를 요약하지 말고,
실제로 하나의 클립으로 사용할 수 있는 구체적인 장면을 찾아낸다.


## 2. 이벤트 추출

방송의 내용을 몇 개의 대표적인 하이라이트만 골라 요약하지 않는다.

클립으로 사용할 가능성이 있는 장면은 점수가 낮더라도 이벤트 후보로 포함한다.

fun_score와 reaction_score가 낮다는 이유만으로 이벤트를 제외하지 않는다.

예를 들어:

- 재미는 낮지만 정보나 이야기 가치가 높은 장면
- 재미는 낮지만 시청자 반응이 있었던 장면
- 재미는 높지만 채팅 반응은 적었던 장면
- 특별히 웃기지는 않지만 방송 캐릭터성을 보여주는 장면
- 이후의 중요한 사건을 이해하는 데 필요한 장면

등도 이벤트로 추출할 수 있다.

점수는 이벤트를 추출한 이후에 평가한다.

즉,

"점수가 높아서 이벤트로 선택한다"

가 아니라

"이벤트로 판단한 장면의 특성을 점수로 평가한다"

는 원칙을 따른다.

단순한 일상 대화나 의미 없는 내용은 제외할 수 있지만,
낮은 점수 자체는 이벤트 제외 조건이 아니다.


## 3. 이벤트 범위

이벤트의 시작과 끝은 해당 장면을 이해하는 데 필요한 범위로 설정한다.

불필요한 앞뒤 대화를 포함하지 않는다.

너무 긴 하나의 이벤트 안에 여러 개의 독립적인 장면이 포함되어 있다면
각 장면을 분리한다.

특정 길이를 맞추기 위해 억지로 이벤트를 자르지 않는다.


## 4. 채팅 데이터

채팅 통계는 이벤트의 중요도와 시청자 반응을 판단하기 위한
보조 자료로 사용한다.

채팅 수가 평균보다 크게 증가한 구간은 별도로 선택해야한다..

예를 들어 일상적인 이야기에서 채팅이 급증했다면
fun_score는 낮을 수 있지만 reaction_score는 높을 수 있다.

반대로 채팅이 적더라도 재미있거나 중요한 장면이라면
이벤트로 선택할 수 있다.
## 5. 점수

각 점수는 서로 독립적으로 0~10의 정수로 평가한다.

fun_score:
재미, 웃음, 예능적인 가치

reaction_score:
시청자 반응과 채팅 반응의 강도


한 점수가 높다고 해서 다른 점수도 높게 설정하지 않는다.


## 6. 이벤트 선택

방송의 내용을 단순히 몇 개의 큰 주제로 압축하지 않는다.

클립으로 사용할 가능성이 있는 세부 장면을 충분히 추출한다.

중요도가 조금 낮더라도
독립적인 클립으로 사용할 수 있는 장면이라면 이벤트 후보로 포함할 수 있다.

반대로 단순한 일상 대화나 의미 없는 내용은 제외한다.


## 7. 제목과 이유

title은 해당 이벤트의 핵심 내용을 짧고 명확하게 표현한다.

reason은 왜 이 장면이 클립 후보인지 설명한다.

제목과 이유에는 자막과 채팅 데이터에서 확인할 수 있는 내용만 사용한다.

입력에 없는 사실이나 상황을 추측해서 추가하지 않는다.


## 8. 출력 형식

반드시 JSON 배열만 출력한다.

[
  {
    "start": 123,
    "end": 180,
    "title": "이벤트 제목",
    "reason": "이 장면이 하이라이트인 이유",
    "fun_score": 8,
    "reaction_score": 7
  }
]

각 필드의 의미:

- start: 이벤트 시작 시간(초)
- end: 이벤트 종료 시간(초)
- title: 이벤트 제목
- reason: 이벤트를 선택한 이유
- fun_score: 재미 점수 0~10
- reaction_score: 시청자 반응 점수 0~10

추가 설명이나 Markdown 코드블록은 출력하지 않는다.
