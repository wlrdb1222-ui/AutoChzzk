# AutoChzzk Multi-Section Highlight Analysis Prompt

## 1. 분석 목적

제공된 방송 자막과 채팅 통계를 분석하여 키리누키 및 클립으로 사용할 만한 장면을 추출한다.

단순히 방송 내용을 요약하거나 전체 방송에서 대표적인 하이라이트만 선정하는 것이 목적이 아니다.

각 분석 구간에서 독립적으로 클립 후보를 탐색하고, 짧거나 중요도가 상대적으로 낮더라도 클립으로 사용할 가치가 있는 장면을 최대한 빠짐없이 추출한다.

모든 분석 구간은 하나의 방송에서 시간 순서대로 이어지는 기록이다.

## 2. 구간별 독립 분석

입력 데이터는 번호가 부여된 여러 분석 구간으로 구성된다.

각 구간을 독립적으로 탐색하되, 전체 방송의 시간적 흐름과 인접 구간의 맥락을 참고한다.

반드시 다음 원칙을 지킨다.

- 각 구간에서 클립 후보를 독립적으로 탐색한다.
- 다른 구간에 더 재미있거나 중요한 장면이 있다는 이유로 현재 구간의 후보를 제외하지 않는다.
- 전체 방송에서 가장 중요한 장면만 골라내거나 후보를 대표 장면 위주로 압축하지 않는다.
- 구간마다 후보 개수를 임의로 제한하지 않는다.
- 각 구간의 분석 결과를 합산했을 때 충분한 수의 세부 이벤트가 남도록 한다.
- 서로 독립적인 장면이라면 같은 주제에 속하더라도 별개의 이벤트로 추출한다.

## 3. 이벤트 추출 기준

점수는 이벤트를 추출한 이후에 평가한다.

즉, 점수가 높아서 이벤트로 선택하는 것이 아니라, 클립으로 사용할 가능성이 있는 장면을 먼저 찾고 그 특성을 점수로 평가한다.

다음과 같은 장면도 후보로 포함할 수 있다.

- 재미있거나 웃긴 장면
- 시청자의 채팅 반응이 급증한 장면
- 방송인의 성격이나 캐릭터성이 잘 드러나는 장면
- 재미는 낮지만 이야기나 정보 측면에서 가치가 있는 장면
- 이후 사건을 이해하는 데 필요한 장면
- 짧지만 독립적인 클립으로 사용할 수 있는 장면
- 점수는 낮더라도 특정 시청자에게 흥미로울 수 있는 장면

단순한 일상 대화나 의미 없는 내용은 제외할 수 있지만, 점수가 낮다는 이유만으로 이벤트를 제외하지 않는다.

## 4. 구간 경계와 맥락 처리

각 분석 구간에는 핵심 분석 대상과 맥락 참고용 자막이 포함될 수 있다.

- 핵심 분석 구간은 실제 이벤트를 탐색해야 하는 범위다.
- 맥락 참고 구간은 대화의 의미, 농담의 원인과 결과, 사건의 진행을 이해하기 위한 자료다.
- 맥락 참고 구간에만 존재하고 핵심 분석 구간과 무관한 장면은 별도 후보로 추출하지 않는다.
- 핵심 분석 구간에서 시작된 이벤트가 경계를 넘어 이어진다면, 맥락을 참고하여 해당 이벤트의 실제 시작과 종료 시점을 판단한다.
- 구간 경계에서 대화가 잘렸더라도 인접 구간의 내용을 통해 하나의 장면임을 파악할 수 있다면 불필요하게 분리하지 않는다.
- 인접 구간에서 동일한 장면이 중복 발견되면 하나의 이벤트로 통합한다.
- 서로 독립적인 장면은 같은 주제이거나 가까운 시간에 발생했더라도 합치지 않는다.
- 이벤트의 시작과 종료 시간은 원본 방송의 절대 시간(초)으로 출력한다.

맥락 참고 자료는 이벤트를 이해하기 위한 보조 자료다. 핵심 분석 구간의 후보 추출 밀도를 낮추는 근거로 사용하지 않는다.

## 5. 채팅 데이터 분석

채팅 통계는 이벤트의 중요도와 시청자 반응을 판단하기 위한 보조 자료다.

- 채팅 수가 평균보다 크게 증가한 구간은 반드시 별도로 검토한다.
- 채팅이 급증했지만 재미가 낮은 장면도 후보로 추출할 수 있다.
- 재미있지만 채팅 반응이 적은 장면도 후보로 추출할 수 있다.
- 채팅 반응이 강하다는 이유만으로 fun_score를 높이지 않는다.
- 채팅 반응이 약하다는 이유만으로 fun_score를 낮추거나 이벤트를 제외하지 않는다.
- 채팅 통계가 제공되지 않는 구간에서는 자막으로 확인할 수 있는 내용만으로 판단한다.

## 6. 점수 평가

각 점수는 서로 독립적으로 0~10의 정수로 평가한다.

### fun_score
장면 자체의 재미, 웃음, 예능적인 가치.

- 0~2: 재미 요소가 거의 없음
- 3~4: 재미 요소가 약함
- 5~6: 어느 정도 재미가 있음
- 7~8: 상당히 재미있거나 인상적임
- 9~10: 매우 강한 재미 또는 뛰어난 예능적 가치

### reaction_score
해당 장면에 대한 시청자의 반응과 채팅 반응의 강도.

- 채팅 통계가 있으면 채팅 급증 여부와 반응 규모를 고려한다.
- 채팅 통계가 없으면 확인 가능한 반응 근거만으로 평가한다.
- 재미 점수와 독립적으로 평가한다.

점수는 전체 방송에서 다른 장면과 비교한 상대적인 순위가 아니다. 각 장면 자체의 특성과 확인 가능한 근거를 기준으로 평가한다.

특정 구간에 재미있는 장면이 많거나 적다는 이유로 점수 기준을 변경하지 않는다.

## 7. 구간별 누락 방지 및 최종 검토

모든 분석 구간을 검토한 뒤 다음 항목을 확인한다.

- 각 핵심 분석 구간에서 후보를 충분히 탐색했는가?
- 짧지만 독립적으로 사용할 수 있는 장면을 놓치지 않았는가?
- 채팅 급증 구간을 별도로 검토했는가?
- 점수가 낮다는 이유만으로 후보를 제외하지 않았는가?
- 하나의 긴 이벤트 안에 여러 독립적인 장면이 섞여 있지 않은가?
- 인접 구간의 경계에서 이벤트가 잘리거나 중복되지 않았는가?

검토 과정에서 누락된 후보를 추가하고 잘못 중복된 후보만 통합한다.

전체 방송을 대표하는 몇 개의 이벤트만 남기기 위해 후보를 다시 압축하지 않는다.

## 8. 제목과 이유

- title은 이벤트의 핵심 내용을 짧고 명확하게 표현한다.
- reason은 해당 장면을 클립 후보로 선택한 이유를 설명한다.
- 자막과 채팅 데이터에서 확인할 수 있는 내용만 사용한다.
- 입력에 없는 사실이나 상황을 추측하지 않는다.
- 서로 다른 이벤트는 제목이 비슷하더라도 각각 유지한다.

## 9. 출력 형식

반드시 JSON 배열만 출력한다. Markdown 코드블록이나 추가 설명은 출력하지 않는다.

[
  {
    "start": 123,
    "end": 180,
    "title": "이벤트 제목",
    "reason": "이 장면이 클립 후보인 이유",
    "fun_score": 8,
    "reaction_score": 7
  }
]

필드 정의:
- start: 이벤트 시작 시간(원본 방송 기준 절대 시간, 초)
- end: 이벤트 종료 시간(원본 방송 기준 절대 시간, 초)
- title: 이벤트 제목
- reason: 이벤트를 선택한 이유
- fun_score: 재미 점수, 0~10 정수
- reaction_score: 시청자 반응 점수, 0~10 정수

시작 시간 기준으로 오름차순 정렬한다.

동일한 이벤트를 중복 출력하지 않는다. 단, 서로 독립적인 장면은 각각 출력한다.
